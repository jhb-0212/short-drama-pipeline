# IP 剧本改编流水线（ip-script-pipeline）

## 概述

把存量网文 IP 稳定地改编成「能过审、可直接用」的短剧/剧集剧本。定位是**只产出剧本**，不碰投流、变现判断、版权评估——那些是别的环节。核心价值：用「开发圣经」保证跨集一致性，用「情绪节拍曲线 + 台词七维诊断 + 台词类型标注 + 情绪光影提示」保证剧本质量，用「模型分层 + 上下文隔离」保证调用经济实惠。剧本产出的人物定妆单 + 简介单 + 资产清单表（字段见 `references/make-spec.md`），作为衔接制作层（分镜/成片）的标准接口。

## 何时使用

- 用户说「把这本小说改成短剧/剧本」「IP 改编」「写先导片/分集剧本」
- 需要从一部网文产出：改编稿 → 先导片剧本 → 分集剧本 → 完整剧本 的完整链路
- 需要稳定、可复用的剧本生产流程（而非一次性即兴写作）

## 流程总览

```
阶段 0  ip-eval         IP 池筛选 + 赛道分流
阶段 A  六阶段编剧链     来源登记→角色开发→开发圣经→分集规划→改编稿→圆桌审核
阶段 B  novel-to-pilot  浓缩成先导片剧本
阶段 C  pilot-to-series 扩展成分集剧本
```

各阶段职责边界（避免重复产出）：
- **A 产出「改编稿」**：保留原文结构、逐章剧本化改写、标注来源等级（直用/改写/新增），**不做分集切分**。
- **B 产出「先导片」**：从改编稿浓缩成 3 分钟独立交付物，只抛问题不揭答案。
- **C 产出「分集剧本 + 完整剧本」**：把改编稿按分集规划**切成逐集**（分集剧本），再**合成连体整本**（完整剧本，供送审/交付）。这才是真正按集交付的成品。

每阶段产出结构化 package，通过「门禁」（必填字段齐全）才进入下一阶段。**每阶段只做一次审核**（A→A6 圆桌审核，B→轻量剧透审查，C→轻量一致性审查），换模型冷审只在全剧收尾时统一做一次，不与各阶段审核重复叠加。

## 执行原则（贯穿全流程）

1. **上下文隔离**：每阶段只喂最小必要上下文，全文绝不重复加载。具体清单见 `references/economy.md`。
2. **模型分层**：便宜模型干粗活（初筛、粗写、多视角审核），贵模型干细活（开发圣经、分集规划、台词精修、冷审）。映射表见 `references/economy.md`。
3. **机械检查优先**：跨集查重、禁词、时间线对齐、道具/人名一致性等「检索/对比」类检查，**先用 Grep 类机械手段跑，清掉低级错误后，剩余的语义问题才进模型视角**。这一条能拦下 60% 以上的返工，是省成本最狠的一招。
4. **校验前置**：把容易返工的点提前校验，宁可前面慢一步，不后面返工一整批。
5. **复用件只生成一次**：开发圣经、人物小传、底牌分层表 + 禁词清单生成后，B/C 阶段直接引用，不重新生成。

## 阶段 0 · ip-eval（IP 池筛选评估）

**输入**：IP 池（番茄 / 阅文火种 / 七猫 / 自有库）+ 目标（国内剧/海外剧/解说叙事）。

**动作**：批量初筛，可并跑多部 IP。只读元数据 + 章节目录 + 前 3 章抽样（不读全文）。

**输出**（评估报告，逐项打点）：
- 赛道分流 + 语速标准（中文字/秒 vs 英文词/秒 vs 解说 4.5~6.5 字/秒）
- 题材热度 / 改编适配度 / 平台匹配 / 商业潜力
- 投资额分级预判（80万+ / 30–80万 / <30万）
- 数据画像（追读率 / 付费转化 / 完读率）

**规则**：不通过 → 换下一部 IP，不救稿。评估报告字段齐全（见 `references/packages.md` 阶段 0 门禁），才放行进阶段 A。

### 🔒 赛道硬分流（阶段 0 必做，未定不进场）

> 赛道不是「写完再补的标签」，而是**决定后续走哪条规则链的硬开关**。阶段 0 必须确定赛道，且三条赛道走不同的规则链——**禁止拿国内剧六阶段链去套海外剧或解说类**。

| 赛道 | 走哪条链 | 语速标准 | 规则入口 |
|---|---|---|---|
| ① 国内剧 | 六阶段编剧链（A1~A6）+ B 先导片 + C 分集 | 中文 4.5~6.5 字/秒 | 现有流程（本文件） |
| ② 海外剧 | 六阶段编剧链（中文写）→ **英文对白适配层** → 海外节奏 | 英文 2.0~2.8 词/秒 | `references/overseas-adapter.md` |
| ③ 解说叙事 | **解说剧本链**（旁白稿 VO Script，非分集对白剧本） | 解说 4.5~6.5 字/秒 | `references/jieshuo-script.md` |

**纪律**：
1. 阶段 0 未确定赛道 → 停下询问，把三条赛道摆出来让用户选，不默认、不推断。
2. 赛道一旦确定，后续所有阶段都按该赛道的规则链走，**不中途混用**（不能「海外剧的语速」配「国内剧的台词风格」）。
3. 语速标准随赛道锁定：国内剧中文字/秒（4.5~6.5）、海外剧英文词/秒（2.0~2.8）、解说 4.5~6.5 字/秒，写进评估报告，后续 A3 开发圣经「台词风格与语速规范」承接。

## 阶段 A · 六阶段编剧链

详见 `references/stage-a.md`（含每一步的 prompt 要点与产出格式）。六步：

1. **A1 来源登记**：记录 IP 来源 + 投资额定档 + AI 标识方案
2. **A2 IP 与角色开发**：人物小传 + 反派养成 + 爽点曲线判定
3. **A3 开发圣经（bible）**：世界观 / 人物定型 / 台词风格 / 平台节奏矩阵 / **底牌分层+揭示节奏表** —— 全局一致性锚点
4. **A4 分集规划**：分季切分 + 钩子分布 + 付费点卡位 —— 唯一人工确认点
5. **A5 改编稿**：逐章剧本化改写 + 来源等级标记（直用/改写/新增）+ 台词类型标注 + 情绪光影提示 + 动作链（**不做分集切分，分集留给阶段 C**）
6. **A6 圆桌审核**：多视角交叉审 + P0 清零（阶段 A 的唯一审核）

产出：改编稿 + **adaptation-package**（字段清单见 `references/packages.md`）。

## 阶段 B · novel-to-pilot（浓缩成先导片剧本）

只加载 adaptation-package 的 highlights + 开发圣经（不加载改编稿全文）。钩子来源按爽点曲线判定分流：开头即爆 → 从开头浓缩；中后期才爆 → 从整季卖点反推。产出 **pilot-package**。详细逐步流程见 `references/stage-b.md`。

**先导片铁律（钩子纪律）**：只抛问题、不揭答案。全剧底牌（真实动机 / 反派真目标 / 情感真相）一律留白，留待正片反转；开场不剧透核心设定；次要势力简化；付费卡点断在「危险+悬念」顶点。详见 `references/quality-modules.md` 的「钩子纪律」。

## 阶段 C · pilot-to-series（扩展成分集剧本）

**把 A 阶段的改编稿按分集规划切成逐集**。每集开写前，先读 A4 分集规划表里本集的「揭示进度标注」锁定本集揭示边界（本集能揭示到什么程度、哪些禁词禁用、时间轴第几日），写入稿件开头注释，再动笔。这是「分集剧本按节奏表走」的硬前提，缺一不写。逐集生成 → 逐集机械检查 → 平台级分级 → 合规精审 → **全集合成完整剧本**。详细逐步流程见 `references/stage-c.md`。产出 **series-package**（含逐集剧本 + 完整剧本）。

## 冷审（全剧收尾，统一一次）

全剧收尾时执行一次：**先机械检查（Grep 类清禁词/查重/时间线）→ 再换模型交叉审（用与生产不同的模型挑错）+ 隔天回看**。检查忠实度 / 一致性 / 合规 / 来源标记。不通过 → 打回对应阶段。**审查对象是阶段 C 合成的「完整剧本」整本**（不是逐集散稿）。**不与各阶段的审核（A6/B 审/C 审）重复**——各阶段审的是「本阶段产出」，冷审审的是「全剧贯通后的交叉一致性」。
