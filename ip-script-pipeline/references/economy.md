# 经济性设计（省 token / 省模型 / 省返工）

> 三原则：① 上下文隔离；② 便宜模型干粗活、贵模型干细活；③ 校验前置，一次过、少返工。第四条新原则：④ **能用机械检查（Grep/脚本）的，绝不用模型**。

## 模型分层表

| 阶段 | 模型档位 | 理由 |
|---|---|---|
| 阶段 0 评估 | 便宜模型 | 批量初筛，可并跑多部 IP，仅产出结构化结论 |
| A2 角色开发 | 便宜模型 | 人物小传是可迭代粗稿 |
| A3 开发圣经 | 贵模型 | 全局一致性锚点，错一处 B/C 全错 |
| A4 分集规划 | 贵模型 | 唯一人工确认点前，必须高质量 |
| A5 改编稿（粗写） | 便宜模型 | 量大，先出 80 分初稿，台词不精修 |
| A6 圆桌审核 | 便宜模型 × 多视角 | 多视角用同一便宜模型跑多次，成本可控 |
| B 先导片浓缩 | 贵模型 | 先导片是「门面」，错一处影响全剧第一印象，值得一次到位 |
| C 分集（切集 + 台词精修） | 便宜模型切集 → 贵模型台词精修 | 台词精修**只在 C 阶段做一次**，A5 不重复精修 |
| B/C 轻量审查 | 便宜模型 | 只挑「剧透/一致性」单点，不全文重审 |
| 冷审（全剧收尾一次） | 贵模型 | 挑错者角色，全剧贯通后一次到位 |

## 机械检查优先（省模型的最狠一招）

> 来源：试跑《跨界追夫》时发现，跨集查重、禁词、时间线对齐这类「对比/检索」检查，用 Grep 一次就能跑完，开模型反而慢且贵。**先机械、后模型**。

| 检查项 | 方式 | 是否开模型 |
|---|---|---|
| 禁词/等义表述查重 | Grep 搜禁词清单 | 否 |
| 跨集钩子重复 | Grep 搜已用钩子关键词 | 否 |
| 时间线对齐（第N日字幕） | Grep 抽全部字幕，人眼核对 | 否 |
| 道具/人名一致性 | Grep 搜道具/人名，看出现位置 | 否 |
| 台词重复（跨场同一句） | Grep 搜长句片段 | 否 |
| 语义级剧透/人设崩 | 需理解语义 | 是（A6 剧透检查视角） |

**执行顺序**：写完一批 → 先跑机械检查（Grep 类）清掉可机械发现的问题 → 剩下的语义问题才进 A6 模型视角。机械检查能拦下 60% 以上的低级错误。

## 上下文隔离清单

| 阶段 | 只加载 | 不加载 |
|---|---|---|
| 阶段 0 | IP 元数据 + 章节目录 + 前 3 章抽样 | 全文 |
| A2 角色开发 | 阶段 0 结论 + 前 5 章 | 全文 |
| A3 开发圣经 | A2 人物 + 世界观相关章节（按需检索） | 全文 |
| A4 分集规划 | 爽点地图 + 章节目录 | 全文 |
| A5 改编稿 | 开发圣经 + 当前章 + 上下文 2 章 | 前 10 章 |
| B 先导片 | adaptation-package 的 highlights + 开发圣经 | 改编稿全文 |
| C 分集 | 改编稿**对应章节**（不是全文）+ 分集规划 + 开发圣经 + 当前集 | 改编稿全文（逐集只取所需章节）、先导片全文 |

> 说明：C 阶段是「消费改编稿」的阶段，但**逐集只加载当集涉及的章节片段**，不一次性加载改编稿全文，控制单次上下文规模。

## 省返工的三处前置校验

1. **A3 开发圣经前**：先校验世界观 / 人设 / 语速三件套自洽，且「底牌分层表」已列出各层揭示集数，不自洽不进 A4
2. **A4 分集规划**：人工确认点前置，规划错比写错 30 集便宜得多
3. **A5 粗写**：每章写完先跑「钩子密度 + 来源标记」机检，不过当场改，不进 A6

## 批量与缓存策略

- 阶段 0 对多部 IP 并跑，先筛出 1 部再进 A，避免逐部全流程跑
- 开发圣经、人物小传等复用件**只生成一次**，B/C 阶段直接引用
- 台词七维诊断只对「每集前 3 句 + 关键转折句」精检，不逐句跑
- **底牌分层表 + 禁词清单是复用件**：A3 生成一次，A5/A6/B/C 全程复用，禁词清单直接喂给 Grep 做机械查重
